# 使用说明

## 最小请求

```text
模式：正文
章节：第 1 章
视角：角色名
核心事件：……
必须结果：……
目标效果：……
篇幅：……
```

## 推荐工作流

1. 先维护项目设定和角色卡，再提出章纲请求。
2. 准备《文风参考文本（非正文剧情）》和当前已有正文，作为作者声音锚点；参考文本不提供剧情事实。
3. 章纲确认后提出正文请求，并附原作资料、入场状态和不可改变事实。
4. 正文先只加载写作档完成草稿；草稿完成后才加载修订档与防拟合协议，最后只输出修订稿。
5. 保存正文与收场状态；下一章只把已确认事实作为上下文。
6. 修订后更新连续性记录，不把修订病征复制进写作上下文。

## 防拟合边界

防拟合协议只判断过度拟合。以下问题必须放到设定卡、章纲或评审处理：原作设定正确性、世界观、角色 OOC、剧情逻辑、跨作品语域。

独立修订时按“硬删 → 限量 → 提示”执行。硬删直接改，限量只在超限时改，提示项标给作者决定；正文流程中不输出扫查过程。

## 模式切换

当用户说“写/续写/重写/成稿”时进入正文模式；“分析/看看问题/打分”属于评审；“列本章事件”属于章纲。表达不明确时先询问模式、视角和必须保留的事实。

## 平台适配

本仓库的规范文件是平台无关 Markdown。若目标 Agent 要求特殊 front matter 或目录名，只增加适配层，不修改 `prompts/` 的规则语义。
